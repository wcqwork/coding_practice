        功能范围与总流程

        「AI数据分析师」是嵌入智慧数据后台的独立分析能力，交互形态为分析工作台（非聊天气泡）：底部悬浮输入框发起分析、主区域展示任务执行流、产出数据看板 + AI 诊断报告。该功能为独立模块，本次仅将入口嵌入智慧数据；系统架构上须与智慧数据解耦，不排除后续独立部署或接入其他系统。本说明仅覆盖功能实现逻辑，供技术开发参考。

        端到端主流程（输入 → 输出）：

        权限校验前置：用户进入功能前即完成智慧数据 + MoliAI 权限校验；无权限则不展示功能入口、无法进入。以下主流程假定用户已具备入口权限。

        flowchart TD P[进入功能前：智慧数据 + MoliAI 权限校验] -->|无权限| P1[不展示入口 / 无法进入] P -->|有权限| A[用户发起：预设场景 或 自由输入] A --> B[点数预检（MoliAI）] B -->|额度不足| B1[拦截：引导充值，不扣点] B -->|通过| C[中枢调度：意图识别 + 业务参数提取] C --> D{四分支校验} D -->|参数不足| D1[待补充任务卡：追问时段] D -->|意图不明| D2[待补充任务卡：展示预设场景] D -->|能力不满足| D3[待补充任务卡：固定拒答 + 展示已支持场景] D -->|完美匹配| E[Planner：选数据接口 + 判定粒度 + 编排] E --> F[预扣点数] F --> G[调用数据接口取数（并行/串行下钻）] G --> H[AI 多维洞察：直出报告 HTML 含 Chart.js 图表] H --> I[报告落库 + 计费确认；失败则退点] I --> J[任务完成：写入分析记录] J --> K[报告详情页：沙箱渲染看板 + AI 诊断]

        关键产出物：① 任务执行流（实时进度）；② 数据看板（模块 A）；③ AI 深度诊断（模块 B）；④ 分析记录（历史）。计费、缓存、权限贯穿全流程。

        📎 提示词、接口字段、场景分析逻辑等具体配置内容不在本说明中展开，统一见配置文档：中控调度 / Agent / 接口 / 场景逻辑 配置文档（企业微信文档）

        页面 / 模块职责与关键逻辑

        分析场景与配置

        场景以分类目录组织（宏观大盘类 / 渠道与营销类 / 转化与线索类 / 潜客雷达类等）。每个场景含：名称、简介、图标、关联系统标签、时段类型（自选/固定）。

        本期已上线 3 个场景：

        场景分析内容时段
        综合流量分析自选时段内流量 / 互动 / 询盘全链路复盘用户自选
        来源渠道分析各渠道流量、互动率与询盘转化对比，识别优质渠道与虚荣流量用户自选
        询盘转化分析表单询盘趋势、高峰日、来源渠道与着陆页贡献拆解用户自选
        • 每个场景显式声明：必填业务参数（当前均为「分析时段」）、所需数据接口、推荐图表与分析逻辑（具体配置见配置文档）。
        • 场景在三处快捷触达：① 欢迎区场景卡片（无任务时展示）；② 输入框获焦时的推荐场景横条（图标 + 名称）；③ 对话结果中的推荐场景——当意图不明或能力不满足时，回复卡片下方展示可点选的推荐场景，点击即按该场景继续。

        触发方式与交互

        「一份报告 = 一次对话」原则：一次对话只产出一份报告。系统识别到明确意图并开始生成报告后，即锁定输入框、隐藏输入框、不再接受新的自由输入（仅展示执行等待动效）；若任务生成失败，允许对该任务重新生成。需要做另一份分析时，新开一次对话（全新开始、不携带上一份的上下文）。

        方式一 · 预设场景快捷分析

        flowchart TD A[点击场景卡片] --> B[弹出日期选择弹窗] B --> C[选择快捷时段 或 手动起止日期] C --> D{该场景+时段是否已有有效缓存?} D -->|是| E[弹窗提示已有缓存，确认后读取缓存直接展示] D -->|否| F[弹窗提示首次分析将扣点，确认后发起任务] F --> G[任务区展示执行进度] E --> H[进入报告详情页] G --> I[任务完成 · 可展开执行过程] I --> J[查看完整看板与报告] J --> H
        • 日期快捷项：近7日 / 近30日 / 上周 / 本月 / 上月 / 上季度，及手动起止日期。
        • 日期弹窗底部按是否命中缓存动态提示：命中→「该时段已有分析缓存，进入后将直接展示（起 ~ 止）」；未命中→「该时段首次分析将扣点（起 ~ 止）」。

        方式二 · 自由输入

        flowchart TD A[输入框获焦] --> B[上方弹出：推荐场景横条 + 推荐分析需求文案] A2[提交分析] --> C{当前对话是否已在生成/已出报告?} C -->|是| C1[输入框已锁定并隐藏，不再接受新输入] C -->|否| E[中枢调度：意图识别 + 参数提取] E --> F{四分支校验} F -->|参数不足| F1[待补充：追问缺失参数] F -->|意图不明| F2[待补充：展示预设场景] F -->|能力不满足| F3[待补充：固定拒答 + 推荐场景] F -->|完美匹配| G[锁定输入框 → 创建执行任务 → 生成报告] G --> H{生成是否成功?} H -->|成功| I[报告完成 · 本次对话结束] H -->|失败| J[可对该任务重新生成]
        • 待补充阶段（缺参数/缺意图/能力不满足）仍属同一次对话，输入框可用、可继续补全；一旦命中意图开始生成即锁定并隐藏输入框。
        • 生成失败或报告完成后，输入框隐藏，仅提供「重新生成」或「开启新对话」。
        • 输入框限制（未执行任务前不扣点，需防 token 浪费）：单次最大 200 字符、每分钟最多 10 次发送（均可配置）。超限提示文案：
          • 超过字符上限：「输入内容过长，单次最多 {max_chars} 个字符，请精简后重试。」（本期 max_chars=200）——禁止发送，不自动截取输入内容，仅提示用户精简。
          • 超过频率上限：「发送过于频繁，每分钟最多 {max_per_minute} 次，请稍后再试。」（本期 max_per_minute=10）

        意图识别与四分支校验

        中枢调度根据用户指令 + 当前对话上下文，输出结构化结果：意图、业务参数、状态标识、缺失项清单。业务参数提取是全局、与意图无关的（如「最近30天」始终落到时段参数）；完整性校验在命中场景后，用该场景的必填业务参数对照。

        技术判断依据：按返回的「状态标识」路由分支

        前端/后端无需做语义二次判断，直接读中枢返回的状态标识决定走哪条分支（状态枚举与判定规则见配置文档）：

        动态参数：scene_name 场景名；missing_field_labels 缺失项中文名（顿号连接，如「分析时段」）；quick_example 快捷示例（如「近7日」）        		不扣

        同一次对话内的参数累积（判断流转示例）

        • 用户先输入「帮我查最近30天的数据」→ 中枢返回：状态=缺意图、参数={时段=30天}（已暂存）→ 走「意图不明」分支，展示推荐场景。
        • 用户在同一对话补一句「来源渠道情况」→ 中枢结合已暂存参数返回：状态=就绪、意图=来源渠道分析、参数={时段=30天} → 直接发起，无需重问时段。

        Agent 调度与执行时序

        后端技术时序与前端进度对应（主进度环节：分析意图 → 获取数据 → 绘制图表 → 数据分析 → 生成优化建议 → 完成，其中「获取数据」含按接口推进的二级进度）。中间状态通过 SSE 实时推送，任务卡同步更新 Loading / 步骤。每次对话相互独立、从零开始，不携带历史对话或上一份报告的任何上下文。

        Planner（任务规划）说明

        • Planner 与意图识别同属调度中枢，工程上可合并为一次大模型调用完成。它的职责是：依据命中的场景配置，确定要调用哪些数据接口、按时段自动判定查询粒度、安排接口的并行/串行（下钻）执行顺序。
        • 预设场景的所需接口已在场景配置中写明，Planner 按配置确定性执行（选接口、判定粒度、编排并行/串行）。本期暂不支持自由输入的复杂诉求动态规划，后续版本扩展。
        • 执行中任务卡内 AI 头像有动效；AI 分析阶段文案：「AI数据分析师 正在分析数据并撰写报告…」。

        数据接口取数与粒度

        数据查询直接调用各业务系统整合后的数据接口（非 PV/UV/IP/会话各自单独接口）。每个接口带标题、能力描述。接口标题统一命名为「查询/获取……数据」格式（如「查询来源渠道数据」）。执行时界面按接口推进进程文案：调用中显示「正在{接口标题}」，返回后显示「已{接口标题}」（示例：「正在查询来源渠道数据」→「已查询来源渠道数据」）。

        编排：并行 + 串行（链式下钻）

        • 并行：互不依赖的接口由调度中枢同时发起以降延迟（如渠道分布与互动转化同时取）。
        • 串行/下钻：由调度中枢按场景配置的执行链路驱动，非大模型临场决定调哪个接口。场景配置中预先声明链路（如：接口 A → 参数映射规则 → 接口 B）。中枢执行流程：① 调用前置接口 A；② 从 A 的返回中按映射规则提取字段（如高转化会话 ID）；③ 将提取值填入后置接口 B 的入参；④ 调用接口 B；⑤ 合并结果交给报告生成。大模型仅参与意图识别与最终报告撰写，不直接调用业务数据接口。

        查询粒度自动判定（按时段跨度，系统判定、不消耗大模型）

        时段跨度（天）粒度示例
        ≤ 14 天按日近 7 天 → 7 个日数据点
        15 ~ 90 天按周近 90 天 → 约 13 个周数据点
        91 ~ 730 天按月近 730 天 → 约 24 个月数据点

        阈值（14 / 90 / 730 天）可配置。单次分析最大跨度为 730 天（2 年）；用户可选择任意历史起止日期，但起止间隔不得超过 730 天。

        输入：站点标识 + 鉴权信息、时段、对比方式（默认环比）、维度、自动判定的粒度。

        「维度」含义：指数据的拆分口径，即按什么把指标拆开看，例如按渠道、按国家/地区、按着陆页、按转化类型等；每个接口支持哪些维度由接口自身定义（见配置文档）。

        输出：统一含成功标识；趋势/对比类同时返回当期值与对比期值。

        「变化率由中枢计算」规则：涨跌幅（环比/同比）由调度中枢用接口返回的当期值与对比期值，按固定公式 (当期 − 对比期) / 对比期 统一计算后写入数据，再交给大模型；大模型只能引用该计算结果，禁止自行编造或推算对比基数与百分比，从而保证口径一致、可核对。

        📎 各接口标题/描述/进程文案、入参出参字段、下钻链路定义见 配置文档。

        图表与报告生成

        方案：AI 用 Chart.js 直出报告 HTML，产品沙箱渲染。

        不再「预设图表库 → AI 选类型 → 前端组装」。改为 AI 结合数据类型自行用 Chart.js 绘制图表、产出图表 HTML/JS，与文字结论拼成整份报告 HTML；产品仅在隔离沙箱（iframe，内置 Chart.js、禁止外部脚本/网络）中渲染。

        flowchart LR A[接口返回数据] --> B[按场景与粒度聚合] B --> C[AI 多维洞察] C --> D[选型并用 Chart.js 绘制图表 HTML] C --> E[撰写三段式诊断] D --> F[拼成整份报告 HTML] E --> F F --> G[HTML 安全校验后落库] G --> H[详情页沙箱渲染：模块A看板 + 模块B诊断]

        HTML 安全校验内容（落库前）

        • 标签/属性白名单：仅允许排版与图表所需标签，过滤 iframe、object、on* 事件属性、javascript: 等危险内容，防 XSS。
        • 脚本范围限制：只允许调用产品内置的 Chart.js 进行绘图，禁止外部脚本、网络请求与跨域资源。
        • 结构与完整性：校验 HTML 可正常解析、图表初始化代码与数据齐全；不通过则判为生成失败并退点。

        报告页两模块（职责分离）

        模块内容原则
        模块 A · 数据看板指标卡、Chart.js 图表、原始数据表呈现可核对的客观数据
        模块 B · AI 深度诊断数据分析、异常说明、优化建议（短/中/长期）基于看板数据给洞察，不替代原始数据

        AI 报告撰写约束

        • 严禁编造数据/图表；变化率必须基于接口返回的对比周期；图表选型结合数据类型（趋势用折线、对比用柱、占比用饼、明细用表格、要点用列表）。
        • 不打质量评分；不使用 P0/P1/P2 等优先级标签；不凭空推测未出现在数据中的结论；核心洞察写报告、明细数字放看板。
        📎 各场景图表组合、报告结构与图表生成规范的具体提示词见 配置文档。

        任务卡状态机与文案

        每次发起分析在任务区生成一张任务卡，状态随执行流转：

        状态界面文案触发可操作
        生成中「生成中」+ 执行进度 + AI 头像动效校验通过、正在取数/分析等待；可展开执行过程
        待补充「待补充」+ 缺项提示 + 快捷选项/可点选场景未识别意图，或已识别意图但必填参数不全（含能力不满足、意图不明）选时段或点选场景以补全
        已完成「已完成」+ 查看完整看板与报告入口报告生成成功并落库查看报告、导出 PDF、重新生成（见分析记录说明）
        生成失败「生成失败」+ 失败/兜底说明仅在已识别明确意图并开始执行任务后，因数据接口失败、AI 生成失败、网络/系统等原因未执行完成重新生成
        • 主进度环节：分析意图 → 获取数据 → 绘制图表 → 数据分析 → 生成优化建议 → 完成；当前步高亮，完成步打勾。
        • 「获取数据」含二级进度：该步内按实际调用的接口逐条展示子进度——「正在{接口标题}」/「已{接口标题}」（不同任务调用接口数量不同，子进度条数随之变化）。
        • 执行进度与提示展示在任务卡片内；任务执行期间隐藏底部输入框，改为展示「任务执行中」的等待动画；执行期间隐藏欢迎场景区。
        • 生成失败或已完成后同样隐藏输入框，仅保留任务卡内操作（重新生成 / 查看报告 / 开启新对话）。
        • 失败兜底文案：「服务暂不可用，请稍后再试。」

        执行过程各环节的「进行中 / 已完成」判定

        环节开始（进行中）结束（已完成 ✓）
        分析意图中枢返回「就绪」、任务进入生成流程Planner 完成接口选取与粒度判定
        获取数据进入本环节；每个接口发起调用时，二级进度显示「正在{接口标题}」该接口返回成功 → 二级进度「已{接口标题}」；全部所需接口均返回成功后本环节完成
        绘制图表取数完成，中枢发起单次大模型报告生成调用见下方「报告生成子阶段」说明
        数据分析同上（逻辑子阶段，非独立调用）同上
        生成优化建议同上（逻辑子阶段，非独立调用）同上
        完成报告 HTML 通过安全校验落库成功并推送前端「完成」事件

        报告生成子阶段（绘制图表 / 数据分析 / 生成优化建议）的进度反馈

        三者在工程上为同一次大模型调用：取数完成后，中枢将数据 + 场景策略 + 图表规范一次性组装进提示词，大模型一次输出整份报告 HTML（含 Chart.js 图表与诊断文案）。前端展示的三个步骤是逻辑进度，由中枢通过 SSE 推送 report_phase 事件驱动，而非三次独立调用：

        • 推荐方式：大模型流式输出时，按提示词约定的阶段标记切换（如输出中出现约定分隔符 / 章节标记 phase:chart、phase:analysis、phase:suggestion），中枢解析后向前端推送对应步骤状态。
        • 兜底方式（无法可靠分段时）：大模型开始处理时，绘制图表、数据分析、生成优化建议三子步同时置为「进行中」；整次调用成功返回后，三子步同时置为「已完成」，再进入「完成」环节（Demo 原型采用此方式）。

        任一步骤发生不可恢复错误 → 任务置「生成失败」，已预扣则退点。

        分析记录与报告详情

        • 分析记录弹窗（历史）：表格字段 = 任务名称（场景 + 时段）、状态（已完成 / 生成中 / 生成失败）、分析日期、提交账号。
        • 操作列规则：
          • 生成失败：展示「重新生成」。点击后返回工作台对话窗口，带入原任务参数（场景 + 时段 + 分析诉求），重新走完整报告生成流程（预扣点；成功则更新该条记录状态为已完成）。
          • 生成中：仅「查看进度」。
          • 已完成：「查看报告」「导出 PDF」「重新生成」。点击「重新生成」后返回工作台对话窗口，带入原任务参数，忽略已有缓存重新取数并 AI 生成（预扣点）；成功后新增一条分析记录并覆盖写入新缓存。
        • 落库时机：在获取到明确任务、开始生成时即落库一条分析记录（状态=生成中），并随执行结果更新为「已完成」或「生成失败」。
        • 重新生成落库：对「已完成」报告再次点击「重新生成」时，新增一条分析记录（状态=生成中），不覆盖原已完成记录；生成成功后原记录保留、新记录标记为已完成。
        • 报告详情页：模块 A 看板 + 模块 B 诊断（AI 生成 HTML）；顶部操作 = 导出 PDF、赞 / 踩、返回工作台。
        • 分析诉求展示（系统层，非 AI HTML 内）：报告页顶部默认展示一行摘要（CSS 单行省略，超出以「…」截断）；仅当文本超出一行可视宽度时显示「详情」按钮，弹窗按时间展示每轮用户输入原文与时间戳。未超出一行则不显示「详情」。预设场景快捷进入则展示场景 + 时段确认文案。
        • 缓存标识（系统层）：展示在模块 A / B 之外（与 AI 生成内容隔离）；命中缓存时显示「首次生成已缓存」及说明文案。

        上下文

        每次对话独立、从零开始：一次对话只产出一份报告，不跨对话、不跨报告携带任何上下文；需要新分析请新开一次对话。上下文仅服务当前这一次对话，避免无限增长：

        层级内容用途 / 时效
        消息上下文当前对话最近 10 轮（系统回复一次记为一轮）；单条用户消息与累计上下文均有最大字符数上限（可配置，本期暂定 10,000 字符，防止未扣费阶段超长输入消耗 token）理解同一对话内的多轮补全；超限截断最早轮次
        任务上下文同一对话内累积「意图 + 已得参数」并记录缺项参数 / 意图补全；仅限本次对话会话内有效，对话结束即清空（不设独立超时）
        站点上下文（行业背景）站点行业、主营、市场语言本期暂不支持（保留设计）

        说明：意图明确并开始生成报告后输入框即锁定；本次对话结束后再发起分析为新对话，不继承上次意图、时段或报告内容。

        缓存与计费

        💡 全局计费说明：所有扣点的具体点数均为待定，且需支持可配置（按次/按场景）。本说明中出现的点数仅为示意，最终以配置为准。
        flowchart TD A[请求某场景某时段分析] --> B{是否命中有效缓存?} B -->|有效| C[直接展示缓存结果，不扣点、不走AI生成] B -->|失效或无| D[预扣点 → 取数 → AI 直出报告] D --> E{生成成功?} E -->|是| F[写入缓存 + 计费确认] E -->|否| G[退点，余额恢复] F --> H[展示结果]
        • 计费规则：按次扣点（非按 token）；开始取数时预扣（点数待定·可配置），生成成功即最终消费，失败退点（无「冻结」概念）。
        • 不扣点情形：参数追问、意图不明引导、能力边界拒答、命中有效缓存。
        • 缓存粒度：同一账号 + 同一场景 + 同一时段视为一次分析；首次生成扣点并写入缓存。
        • 缓存有效期由「AI数据分析师」功能自身决定（非 MoliAI，可配置；本期按一年有效期）：缓存有效→ 直接读取、跳过 AI 生成、不扣点；缓存失效→ 重新走 AI 生成并由 MoliAI 扣点。
        • 界面需区分「首次生成」与「读取缓存」。

        权限校验

        可用性由智慧数据与MoliAI两套权限共同决定，须同时满足。入口权限在发起分析之前校验——无权限用户看不到功能入口。

        flowchart TD A[访问 AI数据分析师] --> B{有智慧数据访问权限?} B -->|否| C[不可进入/提示无权限] B -->|是| D{有 MoliAI 使用权限?} D -->|否| E[可浏览场景说明，不可生成/查看 AI 分析] D -->|是| F{MoliAI 余额充足?} F -->|否| G[提示额度不足，引导充值] F -->|是| H[可正常生成与查看]
        权限来源控制范围
        智慧数据入口可见性、站点数据读取范围、场景与账号数据范围（仅可访问本站点数据，防越权）
        MoliAI仅负责点数扣除与余额校验（是否额度充足、预扣/退点/确认消费）

        两套系统分别校验，前端在发起前给出权限/额度不足提示，避免进入流程后才失败。

        异常与兜底

        异常处理计费
        未开通 / 额度不足预检拦截，引导开通/充值，不进入取数不扣
        参数不足 / 意图不明待补充任务卡，引导补全（保留已得信息）不扣
        能力不满足待补充任务卡 + 固定拒答文案 + 展示推荐场景不扣
        数据接口失败 / 超时重试后仍失败 → 任务「生成失败」+ 兜底文案「服务暂不可用，请稍后再试」；支持重新生成已预扣则退点
        模型失败提示稍后重试 / 兜底说明无法成报告则退点
        数据为空不出图，输出文字说明 / 冷启动建议按配置（建议不扣）
        SSE 中断断线重连补发事件，或直接拉取已完成报告不影响
        重复提交生成中已锁定输入框；同任务幂等不重复扣点不重复扣

        可配置与拓展

        需支持运营可配置、产品可拓展，避免每增一个场景或接口都要发版改码。

        • 场景管理：分类、名称/描述、上线状态、关联系统标签、时段类型、必填参数、所需接口、推荐图表与分析逻辑。
        • 数据接口：接口标题/描述/进程文案、入参出参字段、下钻链路、并行/串行编排规则；后期可接入其他业务系统数据查询能力。
        • 自由输入：推荐场景横条、推荐分析需求文案、不支持维度的兜底说明；输入框字符上限与发送频率限制。
        • 任务展示：进度环节文案、各状态标签与提示文案。
        • 日期快捷项：近7日/近30日/上周等预设与粒度判定阈值可调。
