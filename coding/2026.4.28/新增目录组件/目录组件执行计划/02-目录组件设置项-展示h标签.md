# 02-目录组件设置项，设置展示的 H 标签

## 需求范围

目录组件需要支持设置展示的标题层级：

- 自动提取当前编辑内容中的 `H1` 到 `H6`。
- 默认勾选 `H2`、`H3`。
- 当前内容没有某个层级标题时，该层级勾选项置灰，不允许勾选。
- 勾选层级变更后，编辑器画布中的目录实时刷新。
- 每个目录组件独立保存自己的层级配置。
- 标题层级按正文真实 H 标签计算，不因勾选过滤而改变原始层级关系。

本任务只处理“标题提取 + 层级设置 + 实时刷新”。列表样式、文字样式、颜色、跳转与静态保存分别在后续任务中处理。

## 当前代码依据

- Heading 已在 `phoenix-ai-generate-products/src/components/TiptapEditor/composables/useEditorCreate.js` 中配置 `levels: [1, 2, 3, 4, 5, 6]`。
- 侧栏大纲 `phoenix-ai-generate-products/src/components/OutlineTree.vue` 已有从 HTML 字符串解析 `h1-h6` 的实现，但其层级规则将 `h1/h2` 归为一级、`h3-h6` 归为二级，不满足目录组件保留真实层级的要求。
- iframe 内大纲滚动 `phoenix-ai-generate-products/src/views/editorPage/hooks/useOutlineTracking.js` 使用 DOM 查询 `.tiptap h1...h6`，可参考选择器，但当前按索引定位。
- 目录组件 Node 由任务 01 新增：`phoenix-ai-generate-products/src/components/tiptap-extensions/TableOfContents/index.js`。
- 目录组件工具方法建议放在：`phoenix-ai-generate-products/src/components/tiptap-extensions/TableOfContents/tableOfContentsUtils.js`。

## 数据结构建议

目录项 `items` 建议使用数组：

```js
{
  id: 'toc-heading-xxx',
  text: '标题纯文本',
  level: 2,
  order: 0,
  sourcePos: 123,
  anchor: '',
  hasCustomAnchor: false
}
```

字段说明：

- `id`：内部稳定跳转标识，任务 07 进一步定义。
- `text`：标题纯文本，去除 HTML 标签与多余空白。
- `level`：真实 H 标签层级，`1-6`。
- `order`：标题在可提取标题列表中的顺序。
- `sourcePos`：ProseMirror 文档位置，编辑器内刷新时使用，不建议前台依赖。
- `anchor`：目标标题或区块已有锚点，任务 07 使用。
- `hasCustomAnchor`：是否来自用户设置锚点。

目录组件 attrs：

- `levels`：已勾选层级，默认 `[2, 3]`。
- `availableLevels`：当前正文实际存在的层级，可选择不入库，只在工具栏计算。
- `items`：按 `levels` 过滤后的静态快照。
- `allItems`：不建议入库；如工具栏需要完整标题列表，运行时计算即可。

## 标题提取策略

优先从 Tiptap `editor.state.doc` 提取，而不是从 DOM 或 HTML 字符串提取：

1. 遍历 `doc.descendants`。
2. 找到 `node.type.name === 'heading'` 且 `node.attrs.level` 在 `1-6`。
3. 跳过目录组件自身内部内容。
4. 跳过动态模块容器中的标题，具体规则在任务 08 固化。
5. 使用 `node.textContent.trim()` 作为目录文案。
6. 空标题不生成目录项。
7. 生成 `availableLevels = Set(items.map(item => item.level))`。

如果遇到从 HTML 模式切回内容模式的场景，需要依赖 Node `parseHTML` 恢复目录组件；正文标题仍由 Tiptap schema 解析为 heading。

## 实施步骤

1. 新增标题提取工具。
   - 在 `tableOfContentsUtils.js` 中实现 `extractHeadingItems(editor, options)`。
   - 支持参数：`levels`、`excludeDynamicModules`、`currentTocPos`。
   - 返回 `{ allItems, visibleItems, availableLevels }`。

2. 实现默认层级兜底。
   - 新增目录组件时默认 `levels: [2, 3]`。
   - 如果页面没有 H2/H3，仍保存默认 levels，但展示列表为空，对应工具栏 H2/H3 置灰。
   - 不自动改勾选到其它存在层级，避免用户认知混乱。

3. 实现设置项 UI。
   - 在 `TableOfContentsToolbar.vue` 中新增层级选择控件。
   - 展示 `H1` 到 `H6` 六个按钮/checkbox。
   - 不存在的层级置灰，禁用点击。
   - 至少允许一个可用层级被勾选；如果用户取消最后一个层级，可展示空目录，但建议保留最后一个勾选，减少误操作。该交互需与产品确认，默认按“允许空目录”实现更贴近 checkbox。

4. 更新 Node attrs。
   - 勾选变化时通过 `tr.setNodeMarkup(pos, undefined, nextAttrs)` 更新当前目录组件。
   - 重新计算 `items` 为过滤后的可见目录项。
   - 多个目录组件互不影响，各自保存 `levels` 和 `items`。

5. 实现编辑器内实时刷新。
   - 在 `TableOfContentsView.vue` 或 NodeView 中监听 editor transaction。
   - 当正文 heading 新增、删除、文案修改、层级变化时，重新提取并更新当前组件 `items`。
   - 需要避免更新目录组件自身 attrs 时递归触发死循环：比较新旧 `items` JSON 后有变化才 dispatch。
   - 对同一事务中的多个目录组件，建议通过工具函数批量刷新，减少重复扫描。

6. 处理源码模式切换。
   - 源码模式下用户可能直接改 HTML；切回内容模式后，目录组件按 `parseHTML` 恢复。
   - 第一次 transaction 后刷新 `items`，避免旧快照长期保留。

7. i18n 文案。
   - `editor.tableOfContents.levelsTitle`：展示层级。
   - `editor.tableOfContents.noHeadings`：暂无标题。
   - `editor.tableOfContents.levelDisabledTip`：当前内容没有该层级标题。

## 验收标准

- 新增目录组件后默认只展示 H2、H3 标题。
- 页面存在 H1-H6 时，设置项中对应层级均可勾选。
- 页面缺失某层级时，该 H 层级置灰且无法勾选。
- 勾选/取消勾选后，目录预览立即刷新。
- 过滤后目录项仍保留真实缩进层级，例如只勾选 H3 时仍按 H3 的层级缩进展示。
- 修改正文标题文案后，目录项文案在编辑器内同步更新。
- 新增或删除标题后，可用层级置灰状态同步更新。
- 同一页面存在多个目录组件时，每个组件按自己的 `levels` 展示。

## 风险与依赖

- 动态内容排除规则会影响 `availableLevels`，具体排除容器标识在任务 08 定义。
- 若频繁 transaction 都扫描全文，长文档会有性能压力；建议 debounce 或在 transaction 中判断是否涉及 heading/docChanged。
- 目录组件是 atom Node，NodeView 内部不能用普通文本选区修改标题文案；标题文案编辑在任务 06 的设置项中实现。
