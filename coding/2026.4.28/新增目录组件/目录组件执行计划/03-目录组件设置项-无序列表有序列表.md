# 03-目录组件设置项支持无序列表/有序列表

## 需求范围

目录组件列表样式支持三种状态：

- 无列表。
- 无序列表。
- 有序列表。

默认展示“无列表”。点击列表设置后可在三种状态之间切换。该设置只影响目录组件内部展示，不应调用 Tiptap 正文的 `toggleBulletList` / `toggleOrderedList`，也不改变正文标题结构。

有序列表需要按标题层级生成类似 `1.`、`2.1.`、`2.2.` 的层级编号。无序列表符号样式按设计稿和现有视觉规范实现。

- 块转换列表逻辑位于 `phoenix-ai-generate-products/src/components/FloatingBubbleMenu/composables/useBlockConvert.js`，只作为“不要误用”的参考。
- 工具栏接入点：`phoenix-ai-generate-products/src/components/FloatingBubbleMenu/FloatingBubbleMenu.vue`
- 目录组件工具栏建议：`phoenix-ai-generate-products/src/components/FloatingBubbleMenu/toolbars/TableOfContentsToolbar/TableOfContentsToolbar.vue`
- 目录组件渲染建议：`phoenix-ai-generate-products/src/components/tiptap-extensions/TableOfContents/TableOfContentsView.vue`
- 目录工具函数建议：`phoenix-ai-generate-products/src/components/tiptap-extensions/TableOfContents/tableOfContentsUtils.js`

## 数据结构建议

在目录组件 attrs 中保存：

```js
{
  listStyle: 'none' // 'none' | 'bullet' | 'ordered'
}
```

每个目录项运行时补充：

```js
{
  text: 'Precision Mold Design',
  level: 3,
  displayIndex: '2.1.',
  depth: 1
}
```

说明：

- `level` 是真实 H 标签层级。
- `depth` 是用于视觉缩进的相对层级，建议以当前目录可见项中的最小 H 层级为 0。
- `displayIndex` 仅在 `listStyle === 'ordered'` 时展示。

## 有序编号规则

推荐使用“可见目录项 + 真实层级”的编号策略：

1. 获取过滤后的可见目录项。
2. 找到可见项中最小标题层级 `baseLevel`。
3. 初始化计数器数组 `counters = [0, 0, 0, 0, 0, 0]`。
4. 遍历可见项：
   - 当前层级 `level` 自增：`counters[level - 1] += 1`。
   - 清零更深层级计数器。
   - 如果更浅层级没有计数，补 `1`，避免只勾选 H3 时出现 `.1.`。
   - 输出从 `baseLevel` 到当前层级的非零计数。

示例：

- 可见 H2、H3、H3、H2 输出：`1.`、`1.1.`、`1.2.`、`2.`。
- 只可见 H3、H3 输出：`1.`、`2.`，视觉上仍按 H3 缩进。
- 可见 H2、H4 输出：`1.`、`1.1.`，中间缺失 H3 时不显示空层级。

如果产品要求严格保留缺失层级编号，可在实现前再确认；默认采用连续可读编号。

## 实施步骤

1. 在工具函数中新增编号计算。
   - `decorateTocItems(items, options)`。
   - 输入 `items` 和 `listStyle`。
   - 输出带 `depth`、`displayIndex` 的渲染列表。

2. 在目录组件 attrs 中保存 `listStyle`。
   - 默认值 `none`。
   - `parseHTML` 从 `data-list-style` 读取。
   - `renderHTML` 输出 `data-list-style`。

3. 在 `TableOfContentsToolbar.vue` 增加列表样式按钮。
   - 使用设计稿中的列表图标交互。
   - 点击按 `none -> bullet -> ordered -> none` 循环。
   - 也可做下拉菜单展示三种状态；若按 TAPD “点击切换”理解，优先使用循环切换。
   - 文案：无列表、无序列表、有序列表。

4. 更新当前目录组件。
   - 点击列表按钮时调用 `setNodeMarkup` 更新 `listStyle`。
   - 同时重新计算 `items` 中的 `displayIndex`，或在 View 层根据 attrs 计算。
   - 不调用正文列表命令，不影响 ProseMirror 选区中的段落/标题。

5. 渲染结构。
   - `none`：不渲染 marker，只展示标题文本。
   - `bullet`：渲染自定义 marker，建议使用 CSS 控制圆点，避免原生 `ul` 的默认缩进与设计冲突。
   - `ordered`：渲染编号文本，编号颜色跟随目录文字颜色或按设计稿强调色；若后续要求编号单独颜色，再扩展 attrs。
   - 每项保留统一点击区域，用于任务 07 跳转。

6. 样式联动。
   - 缩进仍按每级 `16px`，不因 marker 类型改变。
   - marker 与文字垂直居中。
   - 超长标题省略规则由任务 06 统一处理。

7. i18n 文案。
   - `editor.tableOfContents.listStyle.none`
   - `editor.tableOfContents.listStyle.bullet`
   - `editor.tableOfContents.listStyle.ordered`

## 验收标准

- 新增目录组件默认是无列表。
- 点击列表按钮后按“无列表、无序列表、有序列表”三态切换。
- 三态切换只影响当前目录组件，不影响正文列表格式。
- 有序列表按层级输出 `1.`、`1.1.`、`2.` 等编号。
- 只勾选深层级标题时，编号从 `1.` 开始，不出现空前缀。
- 无序列表展示 marker，层级缩进仍保持 `16px`。
- 保存 HTML 后重新打开，列表样式和编号展示正确回显。

## 风险与依赖

- 设计稿中的有序编号颜色偏蓝，但文字颜色设置需求要求“修改文字颜色应用所有文字”，默认应让编号跟随文字颜色。
- 如果后续产品要求使用原生 `ol/ul` 语义，需要重新评估静态 HTML 结构与 CSS reset 的影响。
- 编号规则与“跳过未勾选层级时是否保留原始层级编号”存在产品解释空间，当前计划采用连续可读编号。
