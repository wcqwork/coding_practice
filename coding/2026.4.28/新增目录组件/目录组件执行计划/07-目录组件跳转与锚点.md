# 07-目录组件（区块不加锚点，JS 跳转，URL 不变）区块加了锚点取设置锚点，URL 变化

## 需求范围

目录组件点击跳转规则：

- 预览模式和前台页面中，点击目录项滚动到对应章节。
- 区块/标题没有设置锚点时，通过 JS 滚动跳转，URL 不变化。
- 区块/标题已有锚点配置时，使用已设置锚点，跳转后 URL hash 变化。
- 直接访问带 hash 的 URL 时自动滚动到对应章节。
- 支持同一页面存在多个目录组件。
- 多个目录组件需要同步当前阅读位置。
- 兼容页面已有 3.0/4.0 文章目录场景。
- 前台不由目录组件新增或注入独立 runtime；目录组件只输出标准 HTML 与 `data-*` 标记，前台交互接入站点已有全局 JS。

本任务只处理跳转、hash、active 同步逻辑。目录静态生成与动态内容排除在任务 08 处理。

## 跳转标识策略

目录跳转需要同时支持“内部稳定标识”和“用户锚点”。

目录项字段建议：

```js
{
  id: 'toc-heading-abc123',
  text: 'Precision Mold Design',
  level: 3,
  targetId: 'toc-heading-abc123',
  anchor: 'Precision_Mold_Design',
  hasCustomAnchor: true,
  sourcePos: 123
}
```

规则：

- `targetId`：目录组件内部生成的稳定目标 id，用于无锚点 JS 跳转。
- `anchor`：用户已有锚点配置，优先用于 URL hash。
- `hasCustomAnchor`：为 `true` 时，点击目录项使用 `location.hash = anchor` 或 `history.pushState` 更新 URL。
- `hasCustomAnchor`：为 `false` 时，点击目录项调用 `scrollIntoView`，不修改 URL。

## 锚点识别规则

已确认现有锚点可能表现为标题内部的锚点链接，例如：

```html
<h2 class="heading2" id="ld-css-175574207033934050">
  <a href="#iv02ia" data-othertype="anchor" data-urlid="#iv02ia">Industry Solutions</a>
</h2>
```

计划默认按以下优先级识别：

1. 标题内部或相关元素上 `data-othertype="anchor"` 且存在 `data-urlid`，取 `data-urlid` 中的 hash 值。
2. 标题内部锚点链接的 `href="#xxx"`。
3. 标题元素自身或标题所在区块容器上的业务锚点字段，如 `data-anchor` / `data-anchor-id`。
4. 标题元素自身 `id` 或标题所在区块容器 `id`，仅在确认该 id 是前台可访问锚点时使用；避免把样式/组件生成 id 误当业务锚点。
5. 如果没有任何锚点，生成内部 `targetId`，但不把它作为 URL hash 对外暴露。

如果 Phoenix 宿主有更完整的锚点字段规范，应以宿主标准为准，以上规则只作为当前已知 HTML 结构的兼容策略。

## 实施步骤

1. 生成稳定目标标识。
   - 在标题提取时，为每个标题生成 `targetId`。
   - 优先使用已存在锚点作为 `anchor`，但仍保留内部 `targetId`。
   - 无锚点标题生成唯一 `targetId`，可基于标题文本 slug + 顺序 + 简短 hash。
   - 重复标题必须生成不同 `targetId`。

2. 将目标标识写回标题 DOM/HTML。
   - 编辑器内预览时，需要让目标标题可被 JS 找到。
   - 对无锚点标题，可写入 `data-toc-target-id`，不写 `id`，避免 URL hash 暴露。
   - 对已有锚点标题，保留原 `id` 或锚点字段，不覆盖用户设置。
   - 如果 Tiptap Heading schema 不支持对应 attrs，需要扩展 heading 全局属性或通过 `PreserveAttrs` 显式声明。

3. 目录项渲染。
   - 有自定义锚点：渲染 `href="#anchor"`，并带 `data-toc-anchor="anchor"`。
   - 无自定义锚点：渲染 `href="javascript:void(0)"` 或 `button` 语义，并带 `data-toc-target-id="targetId"`。
   - 为避免安全和可访问性问题，推荐使用 `<a href="">` 加点击阻止默认行为；无锚点时 href 可为空或 `#`，点击后 `preventDefault`。

4. 编辑器预览跳转。
   - 在 `TableOfContentsView.vue` 中点击目录项：
     - 有锚点：通过当前 iframe/window 更新 hash 并滚动。
     - 无锚点：查找 `[data-toc-target-id="..."]` 或对应标题 DOM，执行平滑滚动，不改 URL。
   - 滚动容器参考 `OutlineTree.vue` 的 `resolveContainer` 思路，优先当前编辑器滚动容器。

5. 接入前台已有全局 JS。
   - 目录组件不输出独立 runtime，也不在静态 HTML 中注入脚本。
   - 目录组件输出 `[data-table-of-contents]`、`data-toc-anchor`、`data-toc-target-id`、`data-toc-toggle` 等标准标记。
   - Phoenix 站点已有全局 JS 负责绑定目录点击、收起展开、hash 定位和 active 同步。
   - 如果已有全局 JS 缺少能力，应在宿主全局脚本侧扩展目录组件识别逻辑，而不是由目录组件 HTML 自带脚本。

6. URL hash 行为。
   - 有锚点：点击后 URL 更新为 `#anchor`。
   - 无锚点：只滚动，不调用 `history.pushState`，URL 保持不变。
   - 直接访问 hash：
     - 优先 `document.getElementById(hash)`。
     - 再匹配 `[name="hash"]`、`[data-anchor="hash"]`。
     - 找不到则不报错、不阻断页面。

7. 当前阅读位置同步。
   - 前台已有全局 JS 监听页面滚动，用所有目录项的目标元素计算当前 active。
   - 找到当前章节后，为页面中所有目录组件匹配相同 `targetId` 或 `anchor` 的目录项添加 `is-active`。
   - 点击任一目录组件后，立即同步所有目录组件 active 状态。
   - 滚动监听需节流或 `requestAnimationFrame`，避免长文档性能问题。

8. 兼容已有文章目录。
   - 如果页面已有 3.0/4.0 文章目录，并且使用相同锚点/hash，应避免重复抢滚动。
   - 目录组件只管理自身 `[data-table-of-contents]` 内的 active class。
   - 对全局 hash 滚动使用浏览器默认能力优先，脚本只做 offset 修正和无锚点目标补充。

9. 滚动偏移。
   - 当前 `useOutlineTracking.js` 使用顶部偏移约 `10px/150px`。
   - 前台如果有固定头部，需要预留 offset，可读取 CSS 变量 `--toc-scroll-offset`，默认 `10px`。
   - 不同站点可通过 CSS 变量覆盖。

## 验收标准

- 点击无锚点目录项时，页面滚动到对应标题，URL 不变化。
- 点击已有锚点目录项时，页面滚动到对应标题，URL hash 更新。
- 直接访问有效 hash URL 时，页面自动定位到对应章节。
- 直接访问无效 hash URL 时，页面正常展示，无报错。
- 重复标题能跳到正确章节，不串位。
- 同一页面多个目录组件时，滚动页面会同步所有目录组件的 active 项。
- 点击任一目录组件后，其它目录组件 active 状态同步。
- 编辑器预览模式和前台静态页面行为一致。
- 目录组件静态 HTML 不新增内联脚本或独立 runtime，前台交互由站点已有全局 JS 承接。

## 风险与依赖

- 当前仓库现有大纲按标题索引定位，目录组件应改用 id/targetId，避免正文插入标题后旧索引错位。
- 宿主“区块锚点”的真实 HTML 字段需要实现前确认；计划中的 `id/data-anchor` 是默认兼容策略。
- 前台全局 JS 的接入点需要和 Phoenix 宿主联调；如果全局 JS 未扩展目录组件逻辑，前台只能静态显示，无法完成无锚点跳转、收起展开和多目录 active 同步。
- 如果浏览器默认 hash 滚动和全局 JS 滚动同时触发，可能出现二次滚动，需要在全局 JS 中做一次延迟修正。
