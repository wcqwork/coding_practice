# 06-目录组件样式以及交互

## 需求范围

目录组件需要满足设计稿中的视觉和交互要求：

- 默认标题文案 `Table of Contents`，支持翻译，并且已确认需要作为设置项允许用户手动修改。
- 标题字段及箭头支持收起展开。
- PC 和 Pad 默认展开。
- 移动端默认收起。
- 标题最多展示一行，超出省略。
- PC/Pad 目录项最多一行，超出省略。
- 移动端目录项最多两行，超出省略。
- 每行上下间距 `10px`。
- 每级缩进 `16px`。
- 最大高度 `600px`，超出后内部滚动。
- 预览/前台允许点击目录项跳转，具体跳转逻辑在任务 07。
- 同一页面允许多个目录组件，并同步当前阅读位置，具体滚动监听和定位在任务 07。
- loading 加载后台编辑需要有可见状态。

本任务负责视觉结构、响应式、收起展开、标题文案设置和交互状态，不负责静态保存策略。

## 样式结构建议

静态 HTML 结构建议：

```html
<div class="table-of-contents" data-table-of-contents="1">
  <button class="toc-header" type="button" data-toc-toggle="1">
    <span class="toc-title">Table of Contents</span>
    <span class="toc-arrow"></span>
  </button>
  <div class="toc-body">
    <a class="toc-item" data-toc-target="..." style="--toc-depth: 0">
      <span class="toc-marker"></span>
      <span class="toc-text">Heading text</span>
    </a>
  </div>
</div>
```

说明：

- 前台静态 HTML 中不建议使用 Vue 事件；交互通过任务 07 的轻量脚本绑定 `data-*`。
- 编辑器 NodeView 中可以使用 Vue 事件，但输出 HTML 要与前台结构一致。
- `button` 用于标题区域可访问性；如果宿主样式污染 button，可改为 `div role="button" tabindex="0"` 并补键盘事件。

## Node attrs 建议

```js
{
  title: 'Table of Contents',
  collapsedDesktop: false,
  collapsedTablet: false,
  collapsedMobile: true,
  maxHeight: 600,
  loading: false
}
```

说明：

- PC/Pad 默认展开，移动端默认收起。
- 用户手动切换收起展开是运行时状态还是保存状态需要区分：
  - 编辑器内设置项保存默认态：保存到 attrs。
  - 前台用户点击后的展开/收起：只改变 DOM，不写回 HTML。
- `title` 是用户可编辑设置项，默认取 i18n 文案。

## 实施步骤

1. 完成基础样式。
   - `.table-of-contents` 背景使用任务 05 的 `backgroundColor`。
   - 内部 padding 按设计稿补齐，建议先基于截图实现，再由视觉走查微调。
   - `.toc-body` 最大高度 `600px`，超出 `overflow-y: auto`。
   - `.toc-item` 使用 flex 或 block 布局，行间距体现为上下 padding `10px`。
   - 缩进使用 `padding-left: calc(var(--toc-depth) * 16px)`。

2. 实现标题区域。
   - 标题文案来自 attrs `title`。
   - 未设置时使用 i18n 默认 `Table of Contents`。
   - 标题单行省略。
   - 箭头颜色和大小跟随标题文字。
   - 展开时箭头方向按设计稿：PC 图中右上箭头向下表示可收起/展开，需要与移动端图确认；默认实现为展开向上、收起向下，和移动端两张图保持一致。

3. 实现标题文案设置项。
   - 在 `TableOfContentsToolbar.vue` 中新增标题编辑入口，可使用 popover 输入框。
   - 输入保存后更新 attrs `title`。
   - 空值处理：如果用户清空，建议恢复 i18n 默认文案；不保存空字符串。
   - 标题设置只影响当前目录组件。

4. 实现收起展开。
   - 编辑器预览中点击标题区域切换当前组件展开状态。
   - 切换状态不应触发正文选区变化导致工具栏丢失；事件需 `preventDefault`/`stopPropagation` 后再选择当前 Node。
   - 前台静态 HTML 由任务 07 脚本绑定点击。
   - 不同设备默认态通过 body class 或 CSS media query 判断。

5. 实现响应式。
   - PC：默认展开，目录项一行省略。
   - Pad：与 PC 一致。
   - 移动端：默认收起，仅显示标题区域；展开后目录项最多两行省略。
   - 利用 iframe body class：`.device-mobile .table-of-contents` 调整样式。
   - 前台没有这些 body class 时，使用 CSS media query 兜底。

6. 实现 loading 状态。
   - 当目录正在刷新标题快照时，给组件加 `is-loading`。
   - loading 期间展示轻量 loading 或骨架，不阻塞删除/移动。
   - 刷新失败时保留上一次有效 `items`，不让组件空白不可操作。

7. 当前阅读位置状态。
   - 在目录项上支持 `is-active` class。
   - 当前任务只定义样式：active 可使用加粗/下划线/轻微背景或设计补充色。
   - 具体 active 计算、多个目录同步由任务 07 实现。

8. 多目录样式隔离。
   - 每个目录组件独立收起展开。
   - 多个目录组件共享前台 active 状态 class 的更新规则，但不共享配置 attrs。

## 验收标准

- PC 新增目录组件默认展开。
- Pad 与 PC 展示一致。
- 移动端默认收起，只展示标题和箭头。
- 移动端展开后展示目录项，长标题最多两行省略。
- PC/Pad 长标题最多一行省略。
- 每级缩进为 `16px`，每行上下间距为 `10px`。
- 目录区域最高 `600px`，超出内部滚动。
- 标题文案可通过设置项修改并保存回显。
- 标题为空时恢复默认 `Table of Contents`。
- 收起/展开不影响正文标题内容，不导致目录项文字可编辑。
- loading 时有可见反馈，失败时保留上一份目录。

## 风险与依赖

- 设计稿对箭头方向存在轻微歧义，需要视觉验收时确认“展开态/收起态”的箭头方向。
- 当前阅读位置高亮样式在 TAPD 文本中未明确，计划先定义 `is-active` class，最终颜色/样式需设计确认。
- 前台页面 CSS 可能污染 `button`、`a` 默认样式，静态 HTML 样式应尽量使用组件 class 限定。
