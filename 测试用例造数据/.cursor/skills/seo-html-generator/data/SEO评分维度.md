## 第一部分：单页面综合测评维度表 (满分 100 分)

### 🌟 一：全局检测标准与技术申明 (Global Declarations)

在开始逐项检测前，系统必须遵循以下全局规则，以确保数据提取的准确性和唯一性。

#### 1. 网页正文提取规则 (Main Content Extraction)

> **⚠️ 实施优先级**：正文提取与 DOM 清洗**以研发已落地的技术方案为唯一执行标准**；下文规则仅供产品/测评文档对齐与评审参考，若与代码实现不一致，**以代码为准**。

为避免把导航栏、底部链接等“噪音文本”算作正文，爬虫在进行“正文字数、含词次数、首段、文题一致性”检测前，可参考以下优先级清洗 DOM 树：

*   **优先保留（白名单容器）**：命中下列标签/属性的 **DOM 容器及其内部全部子节点文本**，均纳入「主文区」统计（不仅限于容器自身的直接文本）。
*   **白名单示例**：`<article>`, `<main>`, `<div id="content">`, `<div class="post-content">`, `<div class="main">`。
*   **强制剔除（黑名单标签）**：`<nav>`, `<header>`, `<footer>`, `<aside>`, `<script>`, `<style>`, `<iframe>`, `<noscript>`, `<template>`, `<svg>`。
*   **强制剔除（黑名单 Class/ID）**：包含 `menu`, `sidebar`, `footer`, `breadcrumb`, `comment`, `widget`, `popup`, `cookie` 等字眼的 DOM 节点。
*   **提取结果**：剥离上述节点后，提取剩余节点的 `innerText`，作为“清洗后的主文区纯文本”。

#### 2. 重复数据冲突处理规则 (Duplicate Elements Handling)

当抓取到多个相同级别的关键标签时，系统按以下规则收敛：

*   `<title>` 与 `<meta description>`：若存在多个，**只取 HTML 文档流中出现的第一个**，忽略后续重复项。
*   `<h1>` 标签：若存在多个，数量检测记为违规（扣分），在进行“H1含词检测”等后续步骤时，**仅提取第一个 H1 文本进行计算**。
*   `<link rel="canonical">` 标签：若存在多个且指向 URL **完全一致**，记为“轻微代码瑕疵”；若指向 **不同的 URL**，视为搜索引擎无法判断的“致命错误（0分）”。
*   **结构化数据（Google 三种格式均需纳入）**：须**分别扫描**下列三种格式，合并去重后判定；**任一**格式存在可解析且 `@type` 命中白名单（见下文）的实体即通过；**不得仅检测 JSON-LD**。
    *   **JSON-LD**：解析 `<script type="application/ld+json">` 块；`JSON.parse` 成功后读取 `@type`（`@type` 为数组则逐项匹配）。
    *   **Microdata**：解析带 `itemscope` / `itemtype` 的节点；`itemtype` URL 末段映射为类型名（如 `https://schema.org/Product` → `Product`）。
    *   **RDFa**：解析 `typeof` / `property` 声明；将 `typeof` 映射为等效 `@type` 后校验白名单。
    *   **多片段**：同页多段结构化数据时遍历全部片段；**任一片段**合法即通过。

#### 3. 分词/切片与 Jaccard 重叠度计算规则 (Tokenization & Jaccard)

*   **分词规则**：
    *   英文/拼音等拉丁语系：统一转小写（Lowercase），直接按空格和标点符号进行拆分（Split）。
    *   中文/多语言：使用成熟的开源 NLP 分词库（如结巴分词 `Jieba`、Node.js 的 `segment` 等）将长句切分为独立的词汇单元。
*   **Jaccard 重叠度计算对象**：
    *   **对象说明**：是对**单个词汇集合（Sets of Tokens）**进行比对，**而非整句比对**。
    *   **计算公式**：`Jaccard = 交集词汇数 / 并集词汇数`。
    *   **计算步骤**：
        1. 提取文本A（如标题）和文本B（如正文前150词）。
        2. 分别进行分词，得到集合 A 和集合 B。
        3. **去除集合中的“停用词（Stop Words）”**。
        4. 使用上述公式计算最终的 Jaccard 小数值。

#### 4. 多目标关键词处理规则 (Multiple Keywords Handling)

本期“增长引擎”支持为每个页面配置 **1 - 10 个目标关键词**。系统在测评时遵循以下聚合规则：

*   **无目标词时 (N/A 豁免)**：若页面未设置任何目标词，则所有强依赖目标词的检测子项（如：Title/H1/Meta 含词、正文含词、首段点题、语义覆盖等）默认记为“不适用（满分通过）”，并在产品界面灰显提示：“配置目标词以获取更精准的检测建议”。
*   **正向得分指标（取最高分 MAX）**：对于“Title是否包含目标词”、“H1目标词位置”等加分型检测项，系统会**分别计算**这 1-10 个词的单项得分，最终该项得分取**所有目标词中的最高分 (MAX)**。*(业务解释：只要你设置的某一个核心词在标题里完美体现了，这项就得满分)*。
*   **负向惩罚指标（触发任一即扣分 ANY）**：对于“关键词堆砌告警”等惩罚型检测项，系统会分别计算 1-10 个词的频率与密度。**只要其中任意 1 个目标词触发了红线（ANY）**，该项直接记为 0 分（严重错误）。

#### 5. 文本字符长度（Display Length）统一规则

凡涉及 **Title / Meta Description / H1** 等「字符长度」检测的子项，**均调用本规则**，子项表格中**不再重复**写明计长算法：

1. **输入**：待测纯文本 `text`（已 `.trim()`，不含 HTML 标签）。
2. **计算**：遍历字符累加 `Length` —— CJK 统一表意文字、全角符号计 **2**；ASCII 半角字母/数字/常见半角标点计 **1**（与 SERP 展示宽度估算一致，具体 Unicode 范围以研发实现为准）。
3. **输出**：整数 `Length`，注入文案变量 `{length}`；各子项仅写**区间判定**（如 `30 ≤ Length ≤ 60`），**禁止**在区间已隐含非空时再写 `Length > 0` 等冗余条件。

#### 6. 关键词密度（Keyword Density）统一规则

凡「堆砌告警」「含词次数」等涉及密度的子项，**均调用本规则**（与 §4 多目标词规则配合）：

1. **输入**：清洗后主文纯文本 `mainText`、目标词 `keyword`、主文词数 `WordCount`（分词规则见 §3）。
2. **计算**：`Freq` = `keyword` 在主文中的**完整匹配**出现次数；`density`（%）= `(Freq × keyword 按分词计量的词数) / WordCount × 100`（保留一位小数）；`WordCount == 0` 时 `density` 记为 `0`，并触发该子项 N/A 或 0 分（见子项表）。
3. **输出**：`Freq`、`density` 注入 `{freq}`、`{density}`；堆砌红线阈值以「堆砌告警」子项为准（如 `density > 8%` 等）。

#### 7. 检测项不适用（N/A）兜底逻辑

当某子项的**前置条件不满足**，或业务场景**不在该检测维度定义范围内**时：

1. **判定**：触发 N/A（示例：未配置目标词且该项为「含词类」；首页豁免 Slug 含词；非多语站点的 Hreflang；轮播页无 ItemList 要求等 —— 以各子项「判断规则」中的豁免条款为准）。
2. **得分**：该子项记 **满分**（不扣分），并在产品 UI 展示 **「不适用」**（灰显，不参与该子项的问题清单）。
3. **维度聚合**：N/A 子项计入维度满分 `dimMax`，但不计入「严重/建议」触发；若文档未单独定义豁免而遇到未覆盖场景，**默认套用本兜底**（不适用 + 满分），避免误杀。

> 说明：§4「无目标词 N/A 豁免」为兜底逻辑的**专项实例**（仅指**未配置 SEO 目标词**）。**页面缺少 `<title>` / description / H1 等 HTML 字段**时，相关子项在各维度表中记 **0 分**并说明原因，**不适用**本条 N/A 满分。

#### 8. 同域（Same-Site）定义

正文「同站有效内链」中的 **同域** 指：链接目标 URL 与当前页 URL 的 **eTLD+1（注册域）相同**（如 `www.example.com` 与 `blog.example.com` 视为同域；`example.com` 与 `example.co.uk` 不同域）。**默认不以单 host 精确匹配**，除非产品配置显式开启 `same_host_only`。

#### 9. 目标词切片命中率（sliceHitRate）统一规则

凡 Title / Meta / H1 / H2-H6 等子项出现「切片命中率」，**均调用本规则**（与「完整词 `indexOf`」配合）：

1. **分词**：将目标词 `keyword` 按 §3 分词并去停用词，得有序词元数组 `tokens = [w1, w2, …, wn]`；若分词结果为空，则 `tokens = [keyword]`（整词为 1 个 token）。
2. **命中判定**：在待测字段文本 `fieldText`（已 `.trim()`）中，统计有多少个 token 作为**连续子串**出现（英文不区分大小写；中文按分词 token 在 `fieldText` 中子串匹配）。
3. **公式**：`sliceHitRate`（%）= `round(命中 token 数 / n × 100, 1)`，其中 `n = tokens.length`。
4. **与完整词关系**：若 `fieldText` 已包含**完整** `keyword`（连续子串，策略与「含词次数」一致），则不再使用切片档，直接走「完整词 + 位置」区间。
