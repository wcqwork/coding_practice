# SEO 测评场景造数说明

> 适用版本：seo_scenarios_v5（对应 SEO评分维度 最新修订版）  
> 阅读对象：负责构造测试 HTML 页面的开发/测试人员

---

## 零、目标词是什么，在哪里配置

**目标词是独立于 HTML 页面之外的测试输入参数，必须在系统里单独录入，不是 HTML 里写的内容。**

### 是什么

目标词（SEO Target Keywords）是用户在"增长引擎"产品里为某个页面配置的核心关键词，系统会基于这些词去检测页面各字段的命中情况。每个页面可配置 1~10 个目标词。

造数时，目标词有两个独立的来源需要同时准备：

1. **HTML 页面**：在 Title、Meta、H1、正文、图片 Alt、URL Slug 等字段里写入对应内容
2. **系统目标词配置**：在产品的目标词配置入口里，为该页面录入相同的目标词

**两者缺一不可。** 如果只写了 HTML 而忘记在系统里配置目标词，所有含词类检测项会自动走 N/A 满分，测不出任何问题，场景验证将完全失效。

### 影响哪些检测项

配置了目标词才会触发以下检测（否则全部 N/A 满分）：

| 维度 | 受影响的子项 |
|---|---|
| Title | Title 目标词 |
| Meta | Meta 目标词 |
| Headings | H1 目标词 |
| Body | 含词次数、堆砌告警、首段点题（以及文题一致的部分评分逻辑） |
| Media | 主文图片含词 |
| URL | Slug 含词 |

以上 7 个子项共计影响约 **29 分**（满分 100 分的近三成），是场景验证的核心部分。

### 如何配置

在系统目标词配置入口，为测试页面录入场景表「目标词」列的值：

- 大多数场景：`cabinet hinges`（单个目标词）
- M-006 多目标词场景：`drawer slide,cabinet hinges,hardware supplier`（3 个词，逗号分隔）
- M-016 空壳内容场景：`hinges`（单词元词）
- M-036 中文 N/A 场景：`橱柜铰链`（中文词，触发 Slug N/A）
- M-005 全 N/A 场景：**不配置目标词**（留空）

### 多目标词的计分策略

- **正向含词项**（如"Title 目标词"）：对所有目标词分别计分，取**最高分（MAX）**
- **负向惩罚项**（如"堆砌告警"）：任意一个词触发红线，**整项直接 0 分（ANY）**

## 一、整体思路

每个测试场景都基于一个**满分基准页**进行修改。

- **满分基准页（M-001）**：所有 25 个检测子项均满足最优条件，总分 100 分。
- **其他场景**：在满分基准页的基础上，仅修改该场景描述的字段，其余字段保持满分状态。

造数时只需关注「场景/造数要求」列描述的改动点，**不要修改其他字段**。

---

## 二、满分基准页的构造要求

以下是构造满分页需要满足的所有条件，按维度列出。

### Title（16 分）

- 存在唯一 `<title>` 标签，内容非空
- Display Length 在 30~60 之间
- 目标词完整出现，且目标词最后一个字符（lastIndex）≤ 第 60 个 Display Length 字符

### Meta（8 分）

- 存在 `<meta name="description">`，content 非空
- Display Length 在 120~160 之间
- 目标词完整出现，且 lastIndex ≤ 第 160 个 Display Length 字符
- Jaccard 相似度（摘要 vs 正文前 120 词）≥ 0.08

### Headings（18 分）

- 有且仅有 1 个 `<h1>`，文本非空，Display Length ≤ 60
- H1 完整包含目标词
- Title 与 H1 分词后 Jaccard ≤ 0.5（两者差异化）
- 存在至少 1 个 H2–H6 次级标题
- 标题层级无跳级（H1→H2→H3 顺序递进，相邻差值 ≤ 1）

### Body（22 分）

- 正文字数（WordCount）≥ 500（适用页面类型：首页、文章/产品分类页、文章/产品详情页、营销落地/转化页）
- 目标词在正文出现 ≥ 3 次，且 density ≤ 5%
- 目标词首次完整命中的 lastIndex ≤ 600 字符（或占全文 ≤ 10%）
- Title 与正文前 150 词的 Jaccard ≥ 0.1，且正文中含目标词

### Media（5 分）

- 主文区有图片，所有图片均配置非空 Alt
- 至少 1 张图片的 Alt 包含目标词

### URL（6 分）

- 最终 URL 协议为 HTTPS
- Slug 包含目标词英文（适用页面类型：文章/产品分类页、文章/产品详情页）

### Code（25 分）

- 正文至少 1 个高相关同域内链（锚文本含实体词，非无意义词）
- 无 noindex；存在 1 条 https 绝对 Canonical，且指向本页（eTLD+1 一致）
- 配置 og:title、og:description、og:image、twitter:card（content 均非空）
- 若多语言站点：hreflang 成对互链且含 x-default
- 存在至少 1 种结构化数据（JSON-LD / Microdata / RDFa），@type 命中 Google 白名单

## 三、关键技术规则（必读）

### 3.1 Display Length 计算

所有涉及「字符长度」的检测均使用 Display Length，不是字节数也不是字符数组长度：

- CJK 统一表意文字、全角符号：**计 2**
- ASCII 半角字母、数字、常见标点：**计 1**

**示例：**
- `cabinet hinges`（14个ASCII字符）→ Display Length = 14
- `橱柜铰链`（4个CJK字符）→ Display Length = 8
- `Hinges铰链`（6ASCII + 2CJK）→ Display Length = 6 + 4 = 10

### 3.2 目标词位置判定：以 lastIndex 为准

新版所有涉及「位置」的检测（Title目标词、Meta目标词、首段点题）均以目标词**最后一个字符的位置**（lastIndex）判档，不以首字符（firstIndex）判档。

**计算方式：**
1. 从字段文本第 1 个 Display Length 字符开始计数
2. 找到目标词首次完整出现的位置
3. `firstIndex` = 目标词第一个字符的 Display Length 位置
4. `lastIndex` = `firstIndex + 目标词的 Display Length - 1`
5. **以 lastIndex 对照阈值判档**

**示例（Title目标词）：**

Title = `"Best Cabinet Hinges for Furniture"`（Display Length = 34）

目标词 = `cabinet hinges`（Display Length = 14）

- 找到 `cabinet` 从第 6 字符开始（`Best ` = 5字符）
- `firstIndex` = 6，`lastIndex` = 6 + 14 - 1 = 19
- 19 ≤ 60 → **10分满分** ✓

**注意：** 造数时不要按「目标词是第几个单词」来判断位置，要按 Display Length 字符数确认 lastIndex。

### 3.3 关键词密度计算

```
density(%) = (Freq × 目标词分词后的词元数) / WordCount × 100
```

- `Freq`：目标词在正文的完整匹配次数
- `目标词词元数`：目标词分词去停用词后的 token 数量
  - `cabinet hinges` → 2 个词元
  - `hinges` → 1 个词元
  - `橱柜铰链` → 视分词结果，通常 2 个词元
- `WordCount`：正文分词后的总词数

**堆砌红线：**
- density > 8%，或
- Freq > 30 且 density > 5%

→ 触发严重堆砌时，**堆砌告警 和 含词次数同时归 0 分**（联动扣分）

**安全造数参考：**

| 目标词词元数 | Freq | 最小安全 WordCount |
|---|---|---|
| 1（如 hinges） | 3 | 60 |
| 2（如 cabinet hinges） | 3 | 120 |
| 2 | 5 | 200 |

### 3.4 Jaccard 相似度计算

对两个文本分别分词并去停用词，得到词集合 A 和 B：

```
Jaccard = |A ∩ B| / |A ∪ B|
```

造数时不需要精确计算，只需保证语义相关度符合场景要求。**粗略参考：**

- Jaccard ≥ 0.1：两段文本有明显共同词汇（如 Title 和正文开篇都在讲同一产品）
- Jaccard < 0.04：两段文本几乎没有共同词汇（如 Title 讲五金，正文开篇讲旅游）

### 3.5 H1唯一性规则（新版变化）

新版 H1 唯一性只有两档，**没有建议档**：

| 条件 | 得分 | 严重度 |
|---|---|---|
| Count(H1) == 1 且文本非空 | 4分 | 通过 |
| Count(H1) == 0 或 Count(H1) ≥ 2 | 0分 | **严重** |
| Count(H1) == 1 且文本为空 | 0分 | **严重** |

旧版「多个 H1 = 建议 2 分」已废弃，多个 H1 现在直接严重。

### 3.6 层级跳级规则（新版变化）

新版层级无跳级只有两档，**没有建议档**：

| 条件 | 得分 | 严重度 |
|---|---|---|
| 跳级次数 == 0 | 2分 | 通过 |
| 跳级次数 ≥ 1（含仅1次） | 0分 | **严重** |

旧版「1 次跳级 = 建议 1 分」已废弃，任何跳级直接严重。

### 3.7 正文字数的 pageType 条件

正文字数检测**仅对以下页面类型生效**，其余类型自动 N/A 满分：

- 首页
- 文章分类页
- 产品分类页
- 文章详情页
- 产品详情页
- 营销落地页
- 营销转化页

造数时需要在页面 meta 或系统配置里正确设置 `pageType`，否则正文字数检测会被跳过。

### 3.8 Slug 含词的 pageType 条件

Slug 含词检测**仅对以下页面类型生效**，其余类型自动 N/A 满分：

- 文章分类页
- 产品分类页
- 文章详情页
- 产品详情页

首页、营销页等**不在此列**，不会检测 Slug。

## 四、各场景造数要点

### 4.1 基础单点场景（严重）

这类场景只改一个字段，其余保持满分。直接按场景描述操作即可。

**常见的前置条件联动：**

| 改动 | 额外联动影响 |
|---|---|
| 删除 `<title>` | Title/H1差异化 → 0分严重；文题一致 → 0分严重 |
| Title 为空 | 同上 |
| Count(H1) == 0 | H1长度、H1目标词、Title/H1差异化 → 同时 0分严重 |
| H1 文本为空 | H1唯一性、H1长度、H1目标词、Title/H1差异化 → 同时 0分严重 |
| 删除 Meta Description | Meta目标词、文意一致性 → 同时 0分严重 |
| 堆砌触发（density > 8%） | **含词次数联动归 0 分严重**（两项同时扣满） |

### 4.2 M-002 综合建议场景（15 个建议项）

这是一个高密度组合场景，需要同时满足 15 个建议条件：

| 子项 | 目标值 |
|---|---|
| Title 长度 | 60 < Display Length ≤ 100 |
| Title 目标词 | 完整词存在，但 lastIndex > 60 |
| Meta 长度 | 80 ≤ Display Length < 120 或 160 < Display Length ≤ 220 |
| Meta 目标词 | 完整词存在，但 lastIndex > 160 |
| 文意一致性 | 0.04 ≤ Jaccard < 0.08 |
| H1 长度 | 60 < Display Length ≤ 100 |
| 堆砌告警 | 5% < density ≤ 8%，且 Freq ≤ 30 |
| 文题一致 | 0.05 ≤ Jaccard < 0.1 |
| Alt 非空 | 0% < 缺失率 ≤ 20% |
| 主文图片含词 | 所有图片 Alt 均不含目标词 |
| 同站有效内链 | 有同域内链，但锚文本全部命中无意义词黑名单 |
| 收录规范 | 无 `<link rel="canonical">` |
| 社媒分享协议 | 有 og:title + og:description，但缺 og:image 或 twitter:card |
| Hreflang | 有 hreflang 标签但未成对或缺 x-default |
| 结构化数据 | 有结构化标记但 @type 不命中 Google 白名单 |

**建议验证顺序：** 先验证 Title/Meta 目标词 lastIndex 位置逻辑，再验证其他。

### 4.3 M-006 多目标词场景（MAX + ANY）

配置 3 个目标词：

- **A 词**（如 `cabinet hinges`）：在 Title、Meta、H1、正文、图片 Alt 中完整命中，density ≤ 5%
- **B 词**（如 `drawer slide`）：在正文中 density > 8%，触发严重堆砌
- **C 词**（如 `hardware supplier`）：其余字段不含或部分含

验证结果：正向含词类取 A 词的最高分（MAX），堆砌任一触发（B 词）→ 含词次数和堆砌告警均 0 分（ANY）。

### 4.4 M-016 正文字数空壳场景

目标词改用 **单词元词**（如 `hinges`），避免密度问题：

- 正文 WordCount < 100（建议造 60~80 词）
- Freq = 3，density = 3/70 × 100 ≈ 4.3%（安全区间）
- 目标词出现在首 600 字符内（首段点题 3 分）
- Jaccard（Title vs 正文前 150 词）≥ 0.1（文题一致 5 分）

这样可以让正文字数 0 分（严重），同时含词次数、堆砌、首段点题、文题一致保持满分。

### 4.5 M-037 收录规范-多条Canonical相同（冗余）

输出 2 条以上 `<link rel="canonical">`，但所有 href 完全一致：

```html
<link rel="canonical" href="https://example.com/product/cabinet-hinges">
<link rel="canonical" href="https://example.com/product/cabinet-hinges">
```

注意：href 必须完全一致（包括是否有尾斜杠）；不含 noindex。

预期：收录规范 5 分（建议档），Code 21/25，总分 96/100。

## 五、N/A 场景造数说明

N/A（不适用）子项自动记满分，不影响总分。触发条件：

| N/A 触发条件 | 涉及子项 |
|---|---|
| 未配置目标词 | Title目标词、Meta目标词、H1目标词、含词次数、堆砌告警、首段点题 |
| 主文区无图片 | Alt非空、主文图片含词 |
| pageType 不在正文字数适用列表 | 正文字数 |
| pageType 不在 Slug 适用列表 | Slug含词 |
| 非多语言站点 | Hreflang多语言 |
| 目标词为非 ASCII 且无英文别名 | Slug含词（即使 pageType 适用） |

M-005（N/A 综合场景）同时触发上述 11 个 N/A 项，造数时需确认所有 N/A 条件同时生效。

## 六、问题数计数规则

| 严重度 | 计入条件 |
|---|---|
| 严重 | 子项得 0 分 且 严重度标记为「严重」 |
| 建议 | 子项得分 > 0 且 严重度标记为「建议」 |
| 通过 | 子项满分，或 N/A |

总检测项：25 项（文本代码比已从新版移除）。

```
严重数 + 建议数 + 通过数 = 25
```

N/A 项归入「通过」计数，具体口径以产品最终展示为准。
