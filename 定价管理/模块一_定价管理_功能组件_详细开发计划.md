**结论**：该功能之前已被规划和部分开发，但分类在"技术服务"（CATE_ID=5）下且处于停用状态，从未对客户启用。本次需求将其正式归类到"功能组件"（CATE_ID=2）并启用，同时保留"技术服务"中的旧记录不做修改。

### 1.5 询盘来源列的展示控制机制（权限生效原理）

`/inquiryNew/list` 接口通过以下链路判断是否展示"询盘来源"列：

```
PhoenixInquiryNewController.java (第287-291行)
  → funcPriceService.hasFunction(comId, "78")
    → PhoenixFuncRelationDAO.selectRelationByComIdAndOperateType(comId, "78")
      → SQL: SELECT a.* FROM phoenix_func_relation a 
             LEFT JOIN phoenix_func_price b ON a.FUNC_ID = b.FUNC_ID
             WHERE a.COM_ID = #comId# AND b.OPERATE_TYPE = '78'
             LIMIT 1
    → 判断结果非空 且 EXPIRE_TIME 为 NULL 或未过期 → true
  → model.put("hasShowReferSourceAuth", true/false)
```

**控制表**: `phoenix_func_relation`  
**关键字段**:

| 字段 | 说明 |
|------|------|
| COM_ID | 站点ID（当前登录用户会话中的活动站点 ID，通过 `UserContext.getComId()` 获取；注意：非 `phoenix_user.COM_ID` 字段，该字段已废弃固定为 -1） |
| FUNC_ID | 关联 phoenix_func_price 表中 OPERATE_TYPE='78' 的记录 |
| EXPIRE_TIME | 过期时间，NULL 表示永久有效 |
| USE_STATUS | 使用状态，0=使用中 |

**结论**: 只要 `phoenix_func_relation` 中存在一条 COM_ID 匹配且关联 OPERATE_TYPE='78' 的未过期记录，前端询盘列表就会展示"询盘来源"列。该记录在"模块三（为客户开通权限）"时插入。

### 1.6 定价管理页面关键 SQL 查询

```xml
<!-- phoenix_func_price_SqlMap.xml: selectByCate -->
<select id="selectByCate" parameterClass="java.util.Map" resultMap="result4FuncMan">

```

### 子任务 1.1：数据库新增功能权限记录

**目标**: 在 `phoenix_func_price` 表中插入一条记录，使其出现在"定价管理 > 功能组件 > 普通模块"中。

**背景说明**：数据库中已有一条 `OPERATE_TYPE='78'` 的记录，位于"技术服务"分类（CATE_ID=5）且处于停用状态（FUNC_STATUS=0）。本次操作**保留该旧记录不动**，在"功能组件"分类（CATE_ID=2）下新增一条独立记录。

**前置确认 SQL**（确认旧记录存在，不做修改）:

```sql
-- 确认旧记录存在于 CATE_ID=5（技术服务），保留不动
SELECT FUNC_ID, CATE_ID, GROUP_ID, FUNC_STATUS, FUNC_NAME 
FROM phoenix_func_price WHERE OPERATE_TYPE = '78' AND CATE_ID = '5';
```

**SQL 脚本**:

```sql
-- 新增"询盘来源展示"功能权限 - 定价管理 > 功能组件 > 普通模块
INSERT INTO phoenix_func_price (
    FUNC_STATUS, CATE_ID, GROUP_ID, RELATION_ID, OPERATE_TYPE,
    FUNC_NAME, FUNC_PRICE, CHARGE_TYPE, SUPPORT_PLAN, FUNC_CONFIG,
    ADD_TIME, ADDER_NO, ADDER_NAME, UPDATE_TIME, UPDATER_NO, UPDATER_NAME, SHOP_ONLY
) VALUES (
    '1',        -- FUNC_STATUS: 启用
    '2',        -- CATE_ID: 功能组件（定价管理页面）
    '1',        -- GROUP_ID: 普通模块
    NULL,       -- RELATION_ID
    '78',       -- OPERATE_TYPE: 对应 PHOENIX_FUNC_SHOW_REFER_SOURCE
    '询盘来源展示',  -- FUNC_NAME
    0.00,       -- FUNC_PRICE: 0元
    '0',        -- CHARGE_TYPE: 一次性
    '0',        -- SUPPORT_PLAN
    NULL,       -- FUNC_CONFIG
    NOW(),      -- ADD_TIME
    'system',   -- ADDER_NO
    'system',   -- ADDER_NAME
    NOW(),      -- UPDATE_TIME
    'system',   -- UPDATER_NO
    'system',   -- UPDATER_NAME
    '0'         -- SHOP_ONLY: 非商城专属
);
```

**验证 SQL**:

```sql
-- 确认记录已插入
SELECT * FROM phoenix_func_price WHERE CATE_ID = '2' AND GROUP_ID = '1' AND OPERATE_TYPE = '78';
```

## 六、注意事项

1. **CATE_ID=2 的"添加功能"按钮被隐藏**: `plan_config.js` 第 500 行对 cateId=2 隐藏了"添加功能"按钮，所以不能通过页面操作添加，必须通过 SQL 脚本
2. **与模块三的关系**: 模块三（开通功能页面）需要另一条 `CATE_ID=8` 的记录才能让操作员为客户开通该权限。模块一的 CATE_ID=2 记录仅用于定价管理展示
3. **FUNC_ID 自增**: 各环境 FUNC_ID 不同，但不影响逻辑（前端使用 funcId 原始值进行编辑操作）
4. **OPERATE_TYPE 跨分类说明**: 同一 OPERATE_TYPE 可在不同 CATE_ID 下存在多条记录（如 CATE_ID=5 和 CATE_ID=2 各有一条 OPERATE_TYPE='78' 的记录）。权限检查（`hasFunction`）通过 `phoenix_func_relation.FUNC_ID` 关联到具体记录，只要 JOIN 能匹配到 OPERATE_TYPE='78' 即可，不受 CATE_ID 影响。但同一 CATE_ID 内 OPERATE_TYPE 仍应保持唯一，插入前验证：`SELECT COUNT(*) FROM phoenix_func_price WHERE CATE_ID='2' AND OPERATE_TYPE='78'` 应为 0
